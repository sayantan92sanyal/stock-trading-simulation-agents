# Agent Debate Feature — Design Spec

**Goal:** Let the user ask the `trading-boss` agent to run an open-ended debate among the three trader personas (technical, fundamental, retail) on any topic. Traders argue in strict rotation, may change their stated position if genuinely convinced, and individually opt out ("settle") once no further argument will move them. The debate ends when all three have settled, or after 5 minutes of wall-clock time, whichever comes first. The user can watch the debate live in a local browser-based viewer that the boss auto-launches.

**Non-goals:** The debate never triggers a trade. It is purely informational — the user reads the final positions and decides what to do themselves. Debates are not restricted to the current round's ticker universe or to buy/sell/hold framing; any trading-relevant question is fair game (e.g. "should I buy MSFT", "should I rotate from tech into defense").

## Architecture overview

Three new/modified layers, following the project's existing split between deterministic Python state and LLM reasoning:

1. **`scripts/debate.py`** — a new deterministic ledger script (same philosophy as `scripts/portfolio.py`: the LLM never hand-rolls state transitions). Owns the debate transcript file, turn rotation logic, stance-change detection, and the 5-minute wall-clock timeout.
2. **Agent changes** — each of the three trader `.md` files gains a `## Debate mode` section (separate from their existing round-decision instructions). `trading-boss.md` gains a `## Running a debate` section describing the orchestration loop.
3. **`scripts/debate_server.py` + `web/viewer.html`** — a local HTTP server (Python stdlib only, no new runtime dependency) serving a single static viewer page that polls the debate transcript and renders it live, plus three persona icons.

## Debate protocol & stopping rules

- **Topic**: free text, supplied by the user via whatever they ask the boss. No required format.
- **Participants**: always exactly `technical_trader`, `fundamental_trader`, `retail_investor`. The performance reviewer is never involved.
- **Turn order**: strict rotation — technical → fundamental → retail → repeat — skipping any participant who has already settled.
- **Per-turn output**: the speaking trader produces exactly one JSON block:
  ```json
  {
    "agent": "technical_trader",
    "debate_id": "<id>",
    "position_summary": "<one-sentence current stance, free text>",
    "argument": "<the actual reasoning/rebuttal, grounded in the agent's own lens>",
    "status": "continue" | "settle"
  }
  ```
  `settle` still requires a real, final argument — there is no silent pass. A trader whose first turn this is has nothing to rebut yet and simply states an opening position.
- **Stopping conditions**, checked before every new turn is dispatched:
  1. All 3 participants have `status: settled` → debate ends with `end_reason: "all_settled"`.
  2. 5 minutes (300 seconds) have elapsed since `start_time` → debate ends with `end_reason: "timeout"`; any participant still `active` has their most recent `position_summary` frozen as their final position, flagged `forced_by_timeout: true`.
- **Last-holdout rule**: if two participants have settled and exactly one remains `active`, that participant gets exactly one more turn (there's no one left to rebut), after which it is auto-settled regardless of what it said, with its final turn's position recorded as final. This prevents a lone trader looping pointlessly with no opposing argument to respond to. (Implementation note: this is enforced by `append_turn`, not `next_speaker` — see Data model section.)
- **Minimum one argument per participant on the `all_settled` path**: a participant can't be marked settled without having spoken, because settling only ever happens as part of recording that participant's own turn. This guarantee does **not** extend to the `timeout` path: if 5 minutes elapse before a participant ever gets a rotation slot, `check_timeout` still force-settles them with `position_summary` left `null` — see Edge cases.

## Data model — `scripts/debate.py`

File: `data/debates/<debate_id>.json`, atomically rewritten after every turn (same `tempfile` + `os.replace` pattern used by `portfolio.py`'s `_atomic_write`). Falls under the existing `data/` `.gitignore` rule — debate transcripts stay local, same as trade history.

`debate_id` format: `<YYYY-MM-DD>-<short-topic-slug>-<NN>`, mirroring the existing `round_id` convention, generated by `start_debate`.

Shape:
```json
{
  "debate_id": "2026-10-14-should-i-buy-msft-01",
  "topic": "Should I buy MSFT right now?",
  "status": "in_progress" | "complete",
  "start_time": "2026-10-14T20:00:00+00:00",
  "end_time": null,
  "end_reason": null,
  "participants": {
    "technical_trader": {"status": "active", "position_summary": null, "settled_at_turn": null},
    "fundamental_trader": {"status": "active", "position_summary": null, "settled_at_turn": null},
    "retail_investor": {"status": "active", "position_summary": null, "settled_at_turn": null}
  },
  "turns": [
    {
      "turn": 1,
      "agent": "technical_trader",
      "position_summary": "Hold — no clean setup yet.",
      "argument": "RSI14 71.2 is overbought with volume_trend only 0.42x — no confirmation to chase.",
      "status": "continue",
      "stance_changed": false,
      "forced_by_timeout": false,
      "timestamp": "2026-10-14T20:00:05+00:00"
    }
  ]
}
```

### Functions (importable, with a CLI wrapping each)

- `start_debate(topic: str) -> dict` — validates `topic` is non-empty (raises `ValueError` otherwise, same as other scripts' clean-failure pattern). Generates `debate_id`, creates the file with all 3 participants `active`, empty `turns`, `start_time = now()`. Returns the full initial state.
- `next_speaker(debate_id: str) -> str | None` — pure function over the current state: returns the next participant in rotation order who is `active`, or `None` if every participant is `settled` (debate should end). Plain rotation + skip-settled only; it has no special case for "exactly one participant left" — that's handled entirely by `append_turn` (below), so a lone remaining active participant is simply returned normally like any other active participant. Does not mutate anything.
- `append_turn(debate_id: str, agent: str, position_summary: str, argument: str, status: str) -> dict` — validates `agent` is one of the three known ids and is currently `active` (raises `ValueError` if not — e.g. guards against a stray turn for an already-settled agent). Computes `stance_changed` by comparing `position_summary` to that agent's previous turn's `position_summary` (string inequality; first turn is always `stance_changed: false`). Before applying the submitted `status`, checks how many participants were `active` *prior to this call*: if it was exactly 1 (meaning the other two are already settled and this agent is the last-holdout), the submitted `status` is overridden to `"settle"` regardless of what was passed in — this is what enforces the last-holdout rule as a single extra turn, not an open-ended one. Appends the turn with the (possibly overridden) status, updates `participants[agent]` (`position_summary`, and since status is now `"settled"`, sets `status: "settled"`, `settled_at_turn: <turn number>`) whenever status resolves to `"settle"`; otherwise just updates `position_summary` and leaves the participant `active`. After updating, if every participant is now `settled`, finalizes the debate (`status: "complete"`, `end_time: now()`, `end_reason: "all_settled"`). Returns the updated full state.
- `check_timeout(debate_id: str) -> dict` — if the debate is already `complete`, returns the state unchanged. Otherwise compares `now() - start_time` to 300 seconds; if exceeded, finalizes the debate (`status: "complete"`, `end_time: now()`, `end_reason: "timeout"`), and for every still-`active` participant: sets `status: "settled"` (leaving `settled_at_turn: null`, since they didn't settle via their own turn), and marks their most recent turn (if they have one) with `forced_by_timeout: true` — no new turn is synthesized, their existing last `position_summary` simply stands as final. A participant with no turns at all keeps `position_summary: null`. Returns the updated full state.
- `show_debate(debate_id: str) -> dict` — returns the full current state as stored. Raises `FileNotFoundError` if the debate id doesn't exist (consistent with `portfolio.py load_portfolio`'s pattern for a missing portfolio).
- `list_debates() -> list[dict]` — returns `[{"debate_id": ..., "topic": ..., "status": ...}, ...]` for every file in `data/debates/`, most recently started first. Used by the server's `/api/debates` endpoint.

### CLI

`scripts/debate.py start "<topic>"`, `scripts/debate.py next-speaker <debate_id>`, `scripts/debate.py turn <debate_id> <agent> --position "<text>" --argument "<text>" --status continue|settle`, `scripts/debate.py check-timeout <debate_id>`, `scripts/debate.py show <debate_id>`, `scripts/debate.py list`. All follow the existing scripts' pattern: JSON to stdout on success, `{"error": "..."}` to stderr + exit 1 on a caught `ValueError`/`FileNotFoundError`.

## Boss orchestration loop (`trading-boss.md` — new "Running a debate" section)

Runs entirely synchronously inside one boss invocation — no background `Agent()` dispatches for debate turns, avoiding the async coordination issues seen with backgrounded trader dispatches elsewhere in this system. Uses the same subagent-name ↔ agent-id mapping already documented in this file's existing "Agent ids and portfolio ids" table (`technical-trader` ↔ `technical_trader`, etc.) — `debate.py` calls always use the underscored agent id; `Agent()` dispatches always use the hyphenated subagent name.

1. Resolve the topic from the user's request (verbatim free text — no reinterpretation into a ticker/action unless the user's request already is one).
2. `scripts/debate.py start "<topic>"` → get `debate_id`.
3. Check whether the viewer server is already running (a quick local request to `http://localhost:8765/api/debates`; any response, even an error body, means it's up). If not running, launch `scripts/debate_server.py` in the background via Bash (detached, e.g. `nohup ... &disown`). Then run the platform open command (`open` on macOS) against `http://localhost:8765/?debate=<debate_id>`.
4. **Loop:**
   a. `scripts/debate.py check-timeout <debate_id>` — if the returned state's `status` is now `"complete"`, break.
   b. `scripts/debate.py next-speaker <debate_id>` — if the result is empty/null, break.
   c. Dispatch a **foreground** `Agent()` call (`run_in_background: false`) to that trader's `subagent_type`, with a prompt containing: the debate topic, `debate_id`, the full current transcript (from `scripts/debate.py show <debate_id>`), and an instruction to respond in debate mode with exactly one JSON block per its persona file's `## Debate mode` section.
   d. Parse the reply's JSON block. If it fails to parse or is missing required fields, treat this exactly like a forced settle: call `scripts/debate.py turn <debate_id> <agent> --position "<agent>'s last known position, or 'unclear' if none>" --argument "Could not parse this agent's reply — treating as settled." --status settle`, and continue the loop (do not retry, do not abort the whole debate).
   e. Otherwise, call `scripts/debate.py turn <debate_id> <agent> --position "..." --argument "..." --status <continue|settle>` with the parsed fields.
   f. Loop back to (a).
5. Once the loop ends, `scripts/debate.py show <debate_id>` for the final state. Report to the user: each participant's final `position_summary` (noting if `forced_by_timeout`), the `end_reason`, and a pointer to the still-open viewer tab for the full transcript.

## Trader agent changes — `## Debate mode` section in each persona file

Added to `technical-trader.md`, `fundamental-trader.md`, `retail-investor.md`, alongside (not replacing) their existing round-decision instructions:

1. **Given**: the debate topic, `debate_id`, and the full transcript so far.
2. **Decide whether anything in the latest argument(s) changes your mind.** If genuinely persuaded, say so explicitly in `argument` (e.g. "I'm now leaning toward X because of [agent]'s point about Y") rather than silently changing `position_summary` with no acknowledgment. If this is your first turn, there's nothing to rebut yet — state an opening position and argument.
3. **Produce one new argument** from your own lens (technical → indicators/price action only; fundamental → valuation/quality/macro; retail → news/sentiment/momentum), engaging specific points the others made where relevant, not merely restating your opening case verbatim.
4. **Decide `continue` or `settle`.** Settle means "no further argument will change my position this debate" — still requires a real final argument.
5. **Output exactly one JSON block**, per the shape in the Debate protocol section above, and nothing else in the reply.

Traders retain their existing tool access (Bash for market data/indicators/fundamentals, WebSearch) so debate arguments stay grounded in real data, not invented numbers.

## GUI — `scripts/debate_server.py` + `web/viewer.html`

**`scripts/debate_server.py`**: Python stdlib `http.server.ThreadingHTTPServer` with a custom `BaseHTTPRequestHandler`, no new runtime dependency. Routes:
- `GET /` → serves `web/viewer.html`.
- `GET /icons/<name>.png` → serves `web/icons/<name>.png`.
- `GET /api/debate/<id>` → reads `data/debates/<id>.json` via `debate.show_debate`, returns as JSON; 404 with `{"error": "..."}` if not found.
- `GET /api/debates` → returns `debate.list_debates()`.

Default port `8765`, overridable via `--port`. Runs in the foreground when invoked directly (`python3 scripts/debate_server.py`) for a user who wants to start it themselves ahead of time; the boss launches it detached in the background when auto-starting.

**`web/viewer.html`**: single self-contained file, vanilla JS, no build step, no framework.
- Reads `?debate=<id>` from the URL; if absent, fetches `/api/debates` and shows the most recently started one.
- Polls `/api/debate/<id>` every 1.5 seconds via `fetch`.
- Renders: topic header; a status row with all 3 participants, each showing their icon, an "arguing"/"settled" badge, and current `position_summary`; a scrolling transcript of turns below, each showing the speaker's icon, their argument text, and a visual marker when `stance_changed: true`.
- When `status` becomes `"complete"`, shows `end_reason` (plain text: "All three traders reached a final position." / "Debate reached the 5-minute time limit.") and stops polling.
- If `/api/debate/<id>` 404s (debate not found) or no debates exist yet, shows "Waiting for a debate to start..." and keeps polling `/api/debates` at a slower interval (5s) until one appears.

## Persona icons

`web/icons/{technical,fundamental,retail}.png`, 128×128px, flat/simple geometric style (legible at small badge size):
- `technical.png` — candlestick/line chart with an upward trendline, blue/teal.
- `fundamental.png` — a balance scale, gold/green.
- `retail.png` — a speech bubble with a small flame/rocket accent, orange/red.

Generated once via `scripts/generate_icons.py` using Pillow, then committed as static binary assets (not regenerated at runtime). Pillow is added to `requirements.txt` only for this one-time generation — no other part of the system depends on it.

## Testing

`tests/test_debate.py` — full unit coverage, mocking `datetime.now()`/`PORTFOLIOS`-style module-level path constants the same way `test_portfolio.py` does (via `monkeypatch.setattr` on a `DEBATES_DIR` constant and on the module's time source):
- `start_debate` creates a file with 3 active participants, empty turns, and rejects an empty/whitespace-only topic.
- `next_speaker` follows rotation order, skips settled participants, returns `None` once all are settled.
- `append_turn` records the turn, updates participant status on `settle`, detects `stance_changed` correctly (including that a participant's first turn is never a stance change), rejects a turn from an already-settled agent, and auto-finalizes the debate (`all_settled`) when the last active participant settles.
- Last-holdout rule: with two participants already settled, `append_turn` forces the third's status to `"settled"` on its next call *regardless of the `status` value passed in* (including explicitly testing that passing `status="continue"` still results in `settled`), and this triggers the same `all_settled` auto-finalize path.
- `check_timeout` is a no-op before 300 seconds have elapsed (via a mocked clock) and finalizes with `timeout` after, freezing any still-active participants' last turn with `forced_by_timeout: true`; also a no-op if the debate is already `complete`. Includes the case where a participant is force-settled by timeout having never spoken at all (`position_summary` stays `null`).
- `show_debate` raises `FileNotFoundError` for an unknown id; `list_debates` returns debates newest-first.

`tests/test_debate_server.py` — integration smoke test: start the server on an ephemeral port in a background thread, make real HTTP requests against `/api/debates` and `/api/debate/<id>` (seeding a debate file first), assert correct status codes and JSON shape. Not full unit coverage of the thin routing wrapper.

## Edge cases

- Empty/whitespace topic → `start_debate` raises `ValueError`, boss surfaces this cleanly rather than starting a debate with no subject.
- Unparseable or missing-field trader reply mid-debate → recorded as a forced settle with a flagged note; debate continues with remaining active participants; never aborts the whole debate.
- Viewer requests an unknown `debate_id` → server returns 404 with a clean error body; viewer shows "debate not found" rather than a raw error.
- Boss attempts to start the server when one is already listening on the port → detected via health check, skipped; browser still opens to the existing instance.
- A turn's `Agent()` dispatch is in-flight when the 5-minute boundary passes → that turn is still recorded (timeout is only checked *before* dispatching the next turn, not mid-flight), so a debate may run slightly past 300 seconds by at most one turn's duration. This is accepted imprecision, not a bug.
- A participant is force-settled by `check_timeout` before ever getting a single rotation slot → their `position_summary` stays `null` in the final state. The boss's final report should say "never got a turn before time ran out" for that participant rather than reporting a `null` position as if it were a real stance.
